# Database and Python SDK

SpacetimeDB 2.13.0 is the authoritative store for documents, cases, evidence,
mock mailbox messages and leased jobs. It runs locally in Docker at
`http://localhost:3000`, database `accrual-docs`. Records and signing keys persist
in a named Docker volume; original files live separately under `data/files/`.

Only the database module remains TypeScript. The SDK, file storage, parsers,
case/mailbox/job helpers, agent tools, bootstrap, seed and CLI are Python. Node
is needed to build/typecheck the module; generated TypeScript client bindings
and the old Node repositories are no longer used.

## Install and run

From the repository root, with Docker Compose, uv, Node and the SpacetimeDB
2.13.0 CLI installed:

```sh
uv sync --project backend/db
npm --prefix backend/db/spacetime/spacetimedb ci
uv run --project backend/db afterhours-db start
uv run --project backend/db afterhours-db publish
uv run --project backend/db afterhours-db bootstrap
uv run --project backend/db afterhours-db seed
uv run --project backend/db afterhours-db smoke
```

The CLI reads `.env` if present. Equivalent root `npm run db:*` shortcuts invoke
Python. [Setup and handoff](../../docs/SPACETIMEDB_DOCUMENT_STORAGE_SETUP.md)
covers configuration, persistence, authorization and the pipeline.

## Use the SDK

Install into another Python service with `uv pip install -e backend/db` or
`python -m pip install -e backend/db`:

```python
from afterhours_db import AfterHoursDB
from afterhours_db.cases import list_cases, list_facts

with AfterHoursDB.connect("gateway") as db:
    document = db.upload_document(
        data=b"SYNTHETIC contract: hourly rate $100.00",
        original_filename="contract.txt",
        media_type="text/plain",
        type="CONTRACT",
        reference_id="DEMO-ACME-2026-09",
        source_label="demo (SYNTHETIC)",
    )
    metadata, original_bytes = db.read_document(document.id)
    print(document.id, document.upload_key)
    for case in list_cases(db):
        print(case["id"], case["state"], list_facts(db, case["id"]))
```

Document methods include `upload_document`, `add_document_version`,
`get_document`, `read_document`, `list_documents`, `get_version_history`,
`find_by_upload_key`, `find_by_content_hash`, `verify_document`, and `settings`.
Documents are frozen dataclasses with integer IDs, snake_case fields and UTC
`datetime` timestamps. Upload keys are generated by default; retain a key across
retries. Document keys and case import idempotency keys are separate.

Additional modules:

- `cases`: `finalize_import`, `start_review`, `get_case`, `list_cases`,
  `list_facts`, `list_jobs`, `case_document_ids`, `find_case_by_idempotency_key`,
  `is_awaiting_proposal`. Case/evidence rows are snake_case dictionaries.
- `parsers`: CSV/JSON parsing with source excerpts and exact integer-cent strings.
- `mailbox`: `store_email` and `attachment_document_ids` for the synthetic mailbox.
- `jobs`: `list_claimable_jobs`, `claim_job`, `heartbeat_job`, `complete_job` and
  the frozen `JobLease` dataclass. See the [worker integration](../agents/README.md).
- `tools`: scoped `AgentTools` and `AGENT_TOOL_SPECS`; LLM tool names, arguments and
  results retain camelCase. PDF text extraction uses `pypdf`.

`DatabaseConfig` accepts explicit server, database, company, file-store and
secrets paths. `DatabaseConfig.from_env()` reads process environment variables.
The library does not implicitly load `.env`; the CLI does. Relative paths
resolve from the working directory.

## Transport and authority

Gateway calls use authenticated HTTP. `AfterHoursDB.connect("worker")` also
opens a persistent JSON WebSocket for reducer calls: claiming a job requires and
records `ctx.connectionId`. Heartbeat/completion validate the worker identity,
revision, status, token and expiry, without a separate connection ownership
check. Use the same connection for claim, heartbeat and completion. The worker
can submit job results but cannot write documents,
approve reviews, export entries or change policy.

Reads use fresh HTTP queries against authorized views. There is no subscription
cache, replicated client view or event callback API. Helpers fetch the small
demo views and filter/sort locally. SDK calls are synchronous; use a synchronous
FastAPI handler or `asyncio.to_thread` from async code.

`SpacetimeClient.query(sql)` decodes snake_case rows and options.
`call_reducer(name, args)` uses ordered SATS-JSON values and returns no result;
helpers query the view after success. HTTP server failures raise `SpacetimeError`,
and worker reducer failures raise `ReducerError`. Writes are not automatically
retried: an interrupted request may already have committed. This is a project
SDK for this module, not an official general-purpose SpacetimeDB SDK.

The browser must call the Python API, never receive service credentials. The
review create/list/get routes use this SDK; export remains an explicit 501 stub. The gateway calculator saves
unapproved proposals; see the [handoff](../agents/INVESTIGATION.md). Approval
decisions, question delivery and exports are not integrated. The approval watcher's
tested evaluator currently uses explicit mock storage, not authoritative database writes.

## Layout and verification

- `src/afterhours_db/`: installable SDK and CLI; `seed_data/` contains synthetic originals.
- `test/`: unit tests for transports, integrity, parsing, imports and scoped tools.
- `src/afterhours_db/smoke.py`: 23 live storage and pipeline integration checks.
- `spacetime/spacetimedb/src/`: TypeScript schema, reducers and views.
- `spacetime/CLAUDE.md`: module API reference for coding agents.

```sh
uv run --project backend/db python -m unittest discover -s backend/db/test -v
uv run --project backend/db afterhours-db smoke
npm run typecheck
```

A fresh seed creates seven documents (including timesheet v1/v2), four emails,
one Acme case and a queued EXTRACTION job. The amendment is attached to mailbox
mail and excluded from the initial case import. Reruns reuse existing records
and do not rewind a case that workers have already advanced. The frontend Cedar
fixture is independent of this backend scenario.
